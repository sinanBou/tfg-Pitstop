======================================================================
PITSTOP SOFTWARE ARCHITECTURE - DESIGN PATTERNS LOG
======================================================================

1.  REPOSITORY PATTERN (Backend - Spring Data JPA)
    - Implementado en: EmployeeRepository, UserRepository, WorkshopRepository.
    - Propósito: Abstracción total de la capa de datos. Permite cambiar el motor 
      de BD sin afectar la lógica de negocio. Se han añadido consultas personalizadas 
      (JPQL) para búsquedas avanzadas con paginación.

2.  SERVICE LAYER / BUSINESS LOGIC (Backend)
    - Implementado en: EmployeService, WorkshopService.
    - Propósito: Encapsulamiento de la lógica de negocio pura. Garantiza que los 
      controladores solo manejen la comunicación HTTP, delegando la complejidad 
      de las transacciones (@Transactional) y validaciones al servicio.

3.  DATA TRANSFER OBJECT (DTO) PATTERN
    - Implementado en: EmployeeDTO, AddEmployeeRequest.
    - Propósito: Desacoplamiento de las entidades de base de datos del contrato 
      con el frontend. Permite enviar solo los datos necesarios y proteger la 
      estructura interna de la base de datos (seguridad y rendimiento).

4.  FACADE / CUSTOM HOOKS (Frontend - React)
    - Implementado en: useWorkshopAdmin, useStaffAppointment.
    - Propósito: Actúan como una "fachada" que simplifica la interacción de los 
      componentes con la API. Los componentes (TeamTab, OverviewTab) no saben 
      CÓMO se obtienen los datos, solo los consumen.

5.  BUILDER PATTERN (Lombok & Java)
    - Implementado en: Construcción de entidades User y Employee.
    - Propósito: Creación fluida y legible de objetos complejos. Especialmente útil 
      en el registro de empleados para manejar múltiples atributos opcionales 
      como 'address' de forma limpia.

6.  ROLE-BASED ACCESS CONTROL (RBAC) / STRATEGY
    - Implementado en: EmployeeController, TeamTab (Lógica de ascenso).
    - Propósito: Estrategia de seguridad donde las acciones disponibles (borrar, 
      ascender) cambian dinámicamente según el rol del usuario autenticado 
      (OWNER vs MANAGER vs STAFF).

7.  DEBOUNCING PATTERN (Event Handling)
    - Implementado en: Búsqueda de clientes en el modal de citas.
    - Propósito: Optimización de red para prevenir inundaciones de peticiones 
      al servidor mientras el usuario escribe, mejorando drásticamente el rendimiento.
